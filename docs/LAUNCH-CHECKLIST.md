# Public-launch checklist

- [ ] Install dependencies, generate the real lockfile, run full typecheck/lint/build, and resolve all failures.
- [ ] Run the real-app browser tests; check mobile Safari, Android Chrome, keyboard and reduced-motion behavior.
- [ ] Check trademark/name availability and decide whether CRUMB is the final public brand.
- [ ] Independently confirm chain, full contract address, token identity, supply, permissions, tax and ownership disclosures.
- [ ] Publish verified buy/chart/explorer/social HTTPS destinations. Never use lookalike accounts or addresses.
- [ ] Approve and disclose a real token allocation, vesting terms, custody and liquidity arrangements, or retain the visible illustrative label.
- [ ] Integrate a legitimate metrics source through a server-side credential-protected gateway; validate provenance, freshness, availability and CORS. Do not publish fictional counts.
- [ ] Replace concept/prelaunch copy only where a corresponding verified public fact exists. Review footer, community section, roadmap, buy dialog and metadata.
- [ ] Set the actual canonical site origin and inspect social-preview metadata. Supply any project-specific terms, privacy notice and jurisdictional disclosures appropriate to the deployment.
- [ ] Review final dependency/security findings, HTTP headers and CSP for the intended hosting environment. Never expose secrets through NEXT_PUBLIC variables.
- [ ] Measure production performance and inspect layouts at narrow phones, landscape sizes, tablets and wide screens.
- [ ] Confirm there are no claims of audit, locked liquidity, guaranteed returns or official community membership unsupported by actual evidence.

This landing page does not deploy contracts, prove market facts, operate an exchange, or substitute for a project-specific security/legal review.
